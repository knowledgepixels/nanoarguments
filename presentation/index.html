The project

  • Scholarly discussion is scattered across papers, reviews, comments and social media, with no shared structure.
  • Goal: a global discourse and evidence graph, browsable as one resource but federated and distributed.
  • Built on the nanopublication network: small, signed Linked Data snippets with provenance and authorship.
  • Funded through NLnet.

The model

  • Every contribution is a content node: a schema:Statement with its own IRI.
  • Optional subtypes from SIO: hypothesis, evidence, argument.
  • A statement can take a stance toward another (supports, disputes, qualifies), so the graph shows where people agree and disagree, not only who replied to whom.
  • Reuses existing vocabularies: CiTO, Web Annotation, Activity Streams, PROV-O.
sub:statement a schema:Statement ;
  rdf:value "Pigeons can pass a modified mirror-mark test." ;
  cito:disputes <https://w3id.org/np/RAxample/claim> .

Relations and layers

Stance (CiTO)
supports, disputes, extends, agreesWith, qualifies
Threading (Activity Streams)
as:inReplyTo, with or without a stance
Discourse layer
How contributions relate to each other, as direct triples.
Annotation layer
Where a contribution is anchored, for example a quote in a paper, via oa:Annotation.

Vocabulary Survey and Model Specification

In RDF

Each statement is its own nanopub. They connect by pointing at each other's IRIs.

:claim a schema:Statement ;
  rdf:value "Cats knock objects off tables to test gravity." ;
  cito:citesAsEvidence <https://example.org/studies/cat-gravity> .
:support a schema:Statement ;
  rdf:value "Home videos show consistent downward acceleration." ;
  cito:supports :claim .
:counter a schema:Statement ;
  rdf:value "Better explained by a desire for human attention." ;
  cito:disputes :claim .
:rebuttal a schema:Statement ;
  rdf:value "Attention doesn't explain incidents at 3am in empty rooms." ;
  as:inReplyTo :counter ; cito:disputes :counter .
:question a schema:Question ;
  rdf:value "Has anyone repeated this with round tables?" ;
  as:inReplyTo :claim .

Conformance checks for any tool that publishes Nanoarguments nanopubs.

dokieli

  • Annotate any web page and publish the annotation as a signed nanopub.
  • Signing keys managed in the browser, identity via ORCID.
  • See annotations of the current document found on the nanopub network.
  • Notify the annotated document's inbox (LDN).
  • Post to the user's ActivityPub outbox when they have one.
